## 1. 本ドキュメントについて

- 対象範囲：店主専用アプリの機能要件・非機能要件
- 対象外：画面のレイアウト・操作仕様（→ [UI.md](./UI.md)）、データ構造（→ [DATABASE.md](./DATABASE.md)）、実装方法（→ [ARCHITECTURE.md](./ARCHITECTURE.md)）
- 対象外（機能）：お客様が直接操作する画面（予約・注文・決済等）
- 前提：店主本人に加え、店主の代理としてスタッフが同一アプリを利用することを許容する（複数人での利用を想定する）

## 3. 機能要件

> カテゴリ単位で章（3.1, 3.2, ...）を追加していく（例：在庫管理、発注管理、予約管理）

### 3.1 メニュー管理

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| REQ-001 | 商品（メニュー）を名称・価格・大分類／中分類で登録できる | Must | [DATABASE.md](./DATABASE.md#31-menu商品マスタ) Menu |
| REQ-002 | 商品の価格・分類を変更できる | Must | Menu |
| REQ-003 | 販売を終了した商品を一覧から非表示にできる（データは保持し、過去の売上明細には影響しない） | Should | Menu.IsActive |
| REQ-004 | 商品の一覧を閲覧できる | Must | Menu |
| REQ-026 | 商品ごとに原価（概算値）を登録できる | Should | Menu.Cost。粗利益・原価率（REQ-029）の前提 |
| REQ-042 | 商品の中分類を、商品登録に依存せず独立したサブカテゴリーとして作成・名称変更・並び替え・削除できる。大分類（カテゴリー）は初期構築時に定義された固定の分類とし、名称変更のみ可能（追加・削除機能は分析軸を一定に保つため提供しない） | Should | Category, SubCategory。名称変更時は該当する`Menu.CategoryLarge`/`CategoryMedium`を新しい名称に一括更新する（過去の`SalesDetail`のスナップショットには影響しない）。SubCategoryの削除は物理削除（Menu.CategoryMediumは文字列スナップショットのため、削除しても既存商品のデータは壊れない） |

### 3.2 会計処理（売上登録・レジ締め）

> 会計は手書き伝票・手動計算・現金授受まで完了した後、営業終了後にまとめてデータ化する運用を前提とする（[DATABASE.md](./DATABASE.md#32-sales会計ヘッダ)参照）。「会計管理」（会計の作成・編集、カテゴリ×商品のグリッド選択によるカード式UI）と「清算」（レジ締め作業）の2つのタブで構成する（[UI.md](./UI.md) SCR-002参照）

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| REQ-005 | 確定済みの会計内容を、営業終了後にまとめてアプリへ入力できる | Must | Sales |
| REQ-006 | 1件の会計につき、複数の商品・数量を明細として入力できる | Must | SalesDetail |
| REQ-025 | メニューに登録されていない商品や、標準と異なる数量・内容の注文（例：おかわりの1個追加）を、その場で商品名・金額を入力して明細に記録できる | Must | SalesDetail.MenuId（任意）。カテゴリ別集計には反映されない |
| REQ-007 | 合計金額は明細の商品単価・数量から自動計算される | Must | Sales.TotalAmount |
| REQ-008 | 会計ごとに人数を入力できる | Must | Sales.PartySize |
| REQ-009 | 会計に使用した座席（カウンター／テーブル）を任意で入力できる | Should | Sales.SeatId |
| REQ-010 | 会計に顧客を任意で紐づけられる | Should | Sales.CustomerId |
| REQ-011 | 営業日ごとに天候を記録できる | Must | BusinessDay.Weather |
| REQ-022 | 入力済みの会計データ（会計・明細）はいつでも修正・削除できる | Must | Sales, SalesDetail。関連する顧客の来店集計の扱いは[DATABASE.md](./DATABASE.md#5-データ管理方針)参照 |
| REQ-039 | 営業日ごとの準備金（レジ内の釣り銭準備金）を入力・修正できる | Should | BusinessDay.StartingCash。いつでも入力・修正可能 |
| REQ-040 | 対象日の現金売上額・予想現金残高を確認できる | Should | Sales, BusinessDay.StartingCash。支払いは現金固定のため現金売上額＝合計金額 |
| REQ-041 | レジクローズ（締め作業の実施記録）を行い、実施日時の履歴を確認できる | Should | RegisterCloseLog。ロックは行わず、同一日に複数回実施可能 |

| REQ-051 | 経費区分ごとの月次予定額と実績・達成率を確認できる。12ヶ月分を一覧で比較できる | Should | ExpenseCategory, ExpenseTarget, Expense |

## 5. 用語

| 用語 | 意味 |
|---|---|
| 店主 | このアプリの唯一の利用者。スプレッドシートを直接操作しない |
| Decision | ユーザーがChatGPTと要件定義・設計を進めた結果として共有される決定事項。仕様として扱う |
| Single Source of Truth | Googleスプレッドシートを唯一の正とするデータ管理方針 |
| Must / Should / Future | 要件の優先度区分（必須／推奨／将来対応） |

- 本ドキュメント固有の用語もここに追加していく
