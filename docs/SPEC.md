## 1. 本ドキュメントについて

- 対象範囲：店主専用アプリの機能要件・非機能要件
- 対象外：画面のレイアウト・操作仕様（→ [UI.md](./UI.md)）、データ構造（→ [DATABASE.md](./DATABASE.md)）、実装方法（→ [ARCHITECTURE.md](./ARCHITECTURE.md)）
- 対象外（機能）：お客様が直接操作する画面（予約・注文・決済等）
- 前提：店主本人に加え、店主の代理としてスタッフが同一アプリを利用することを許容する（複数人での利用を想定する）

## 3. 機能要件

> カテゴリ単位で章（3.1, 3.2, ...）を追加していく（例：在庫管理、発注管理、予約管理）

### 3.1 メニュー管理

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| REQ-001 | 商品（メニュー）を名称・価格・大分類／中分類で登録できる | Must | [DATABASE.md](./DATABASE.md#31-menu商品マスタ) Menu |
| REQ-002 | 商品の価格・分類を変更できる | Must | Menu |
| REQ-003 | 販売を終了した商品を一覧から非表示にできる（データは保持し、過去の売上明細には影響しない） | Should | Menu.IsActive |
| REQ-004 | 商品の一覧を閲覧できる | Must | Menu |
| REQ-026 | 商品ごとに原価（概算値）を登録できる | Should | Menu.Cost。粗利益・原価率（REQ-029）の前提 |

### 3.2 伝票入力（売上登録）

> 会計は手書き伝票・手動計算・現金授受まで完了した後、営業終了後にまとめてデータ化する運用を前提とする（[DATABASE.md](./DATABASE.md#32-sales会計ヘッダ)参照）

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| REQ-005 | 確定済みの会計内容を、営業終了後にまとめてアプリへ入力できる | Must | Sales |
| REQ-006 | 1件の会計につき、複数の商品・数量を明細として入力できる | Must | SalesDetail |
| REQ-025 | メニューに登録されていない商品や、標準と異なる数量・内容の注文（例：おかわりの1個追加）を、その場で商品名・金額を入力して明細に記録できる | Must | SalesDetail.MenuId（任意）。カテゴリ別集計には反映されない |
| REQ-007 | 合計金額は明細の商品単価・数量から自動計算される | Must | Sales.TotalAmount |
| REQ-008 | 会計ごとに人数を入力できる | Must | Sales.PartySize |
| REQ-009 | 会計に使用した座席（カウンター／テーブル）を任意で入力できる | Should | Sales.SeatId |
| REQ-010 | 会計に顧客を任意で紐づけられる | Should | Sales.CustomerId |
| REQ-011 | 営業日ごとに天候を記録できる | Must | BusinessDay.Weather |
| REQ-022 | 入力済みの会計データ（会計・明細）はいつでも修正・削除できる | Must | Sales, SalesDetail。関連する顧客の来店集計の扱いは[DATABASE.md](./DATABASE.md#5-データ管理方針)参照 |

### 3.3 顧客管理

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| REQ-012 | 顧客をニックネームで登録できる | Must | Customer.CustomerName |
| REQ-013 | 伝票入力時、登録済みの顧客を検索・選択できる（一致がなければその場で新規登録できる） | Must | [UI.md](./UI.md) 伝票入力画面（SCR-002）メモ参照 |
| REQ-014 | 顧客の電話番号を任意で記録できる（識別用途ではなく、将来の予約対応の連絡先） | Should | Customer.PhoneNumber |
| REQ-015 | 顧客ごとの来店回数から新規／リピートを判別できる | Must | Customer.VisitCount |
| REQ-023 | 顧客ごとに、よく注文する商品（メニュー）の傾向を参照できる | Should | SalesDetail.CustomerId（予約の電話対応時などに、その顧客の好みを確認する用途を想定） |

|---|---|---|---|

### 3.5 売上分析・レポート

| ID | 要件 | 優先度 | 備考 |
|---|---|---|---|
| REQ-017 | 期間（日次／週次／月次）を指定して売上（合計金額・客単価）を確認できる | Must | Sales |
| REQ-024 | 期間を指定して、来店人数（合計人数）・来店組数（会計件数）を確認できる | Must | Sales.PartySizeの合計（人数）、Sales件数（組数） |
| REQ-018 | 商品別・カテゴリ別の売上・販売数量、および売上構成比（フード比率／ドリンク比率等）を確認できる | Should | SalesDetail, Menu |
| REQ-019 | 曜日・天候別の売上・来店人数の傾向を確認できる | Should | BusinessDay |
| REQ-020 | 顧客の新規／リピート傾向を確認できる | Should | Customer |
| REQ-021 | 座席（種別）ごとの日次利用件数を確認できる | Should | Seat |
| REQ-036 | ダッシュボード画面で、直近の営業日の売上サマリー（売上高・客単価・来店組数など）をすぐに確認できる | Must | Sales, SalesDetail |
| REQ-037 | ダッシュボード画面で、過去データとの比較に基づく一言アドバイスを確認できる（例：先週同曜日比の増減、直近の売れ筋商品） | Should | Sales, SalesDetail。天候に基づく事前予測（例：天候による売れ筋予測）は対象外。当日の予報天気を持つ手段が現状ないため（[DATABASE.md](./DATABASE.md#5-データ管理方針)のTODO参照） |
| REQ-029 | 商品別・期間別の粗利益・原価率を確認できる | Should | Menu.Cost, SalesDetail.UnitCost（原価未登録の商品は集計対象外） |
| REQ-030 | 商品を売上順にランキング表示できる | Should | SalesDetail, Menu |
| REQ-031 | 売上構成比に基づくABC分析（重点管理商品の抽出）を確認できる | Should | SalesDetail, Menu |
| REQ-032 | 顧客の常連率（期間内の来店のうちリピート来店が占める割合）を確認できる | Should | Sales.CustomerId, Sales.SalesDate。[DATABASE.md](./DATABASE.md#5-データ管理方針)の算出上の注意点を参照（`Customer.VisitCount`をそのまま使わない） |
| REQ-033 | 月次売上の推移、前年・前月・季節ごとの比較を確認できる | Should | Sales |
| REQ-034 | 平均注文点数（商品数量÷客数）を確認できる | Should | SalesDetail.Quantity, Sales.PartySize |

## 5. 用語

| 用語 | 意味 |
|---|---|
| 店主 | このアプリの唯一の利用者。スプレッドシートを直接操作しない |
| Decision | ユーザーがChatGPTと要件定義・設計を進めた結果として共有される決定事項。仕様として扱う |
| Single Source of Truth | Googleスプレッドシートを唯一の正とするデータ管理方針 |
| Must / Should / Future | 要件の優先度区分（必須／推奨／将来対応） |

- 本ドキュメント固有の用語もここに追加していく
